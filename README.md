# Reading Diary

Личный читательский дневник в браузере: библиотека, прогресс, таймер чтения,
статистика, цель и заметки. Одна ссылка, один интерфейс на iPhone и Android —
ничего устанавливать не нужно.

**Открыть:** https://zakhvatov.github.io/reading_diary/

## Что внутри

- полки «Хочу прочитать», «Читаю», «Прочитано», «Не дочитал»;
- добавление книги вручную, поиском по Open Library / Google Books или по ISBN;
- сканер штрихкода ISBN с ручным вводом как запасным вариантом;
- таймер чтения и ручные сессии;
- календарь, статистика, годовая цель и серия дней;
- дневник с заметками и цитатами;
- экспорт и импорт резервной копии.

## Данные

Приложение работает без аккаунта и без сервера. Книги, сессии и заметки
хранятся только в браузере на вашем устройстве (IndexedDB). На GitHub не
уходит ничего, кроме кода приложения. Резервная копия — обычный файл, который
можно сохранить в Files или Drive.

## Стек

Vite, React, TypeScript, Tailwind CSS, Dexie, `vite-plugin-pwa`.
Хостинг — GitHub Pages, публикация через GitHub Actions.

## Локальный запуск

```bash
npm install
npm run dev
```

Сборка:

```bash
npm run build
```

Проверка сборки под GitHub Pages:

```bash
BASE_PATH=/reading_diary/ npm run build
```

## Запуск в Docker

Собрать production-версию и открыть её как обычное веб-приложение на компьютере:

```bash
docker compose up --build
```

Затем открыть **http://localhost:8080**. Внутри — nginx со статикой и
SPA-fallback, поэтому глубокие ссылки вроде `/books/:id` работают и при
обновлении страницы.

Остановить:

```bash
docker compose down
```

Порт можно поменять в `docker-compose.yml` (`"8080:80"`), а собрать образ
вручную — так:

```bash
docker build -t reading-diary .
docker run --rm -p 8080:80 reading-diary
```

Данные по-прежнему хранятся в браузере на этом компьютере: контейнер отдаёт
только файлы приложения и ничего не сохраняет между запусками.
